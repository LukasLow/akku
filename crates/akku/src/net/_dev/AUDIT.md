### Suggested fixes for Worker

1. **CRITICAL (coop budget):** add a per-task cooperative budget, as tokio's `coop` does. Keep it in `task` thread-local state, reset it in `Shared::run_task` (and for each root poll) to about 128, and consume one unit in `Registration::poll_ready` (or `poll_io`) on every `Ready` result. When the budget is exhausted, call `cx.waker().wake_by_ref()` and return `Pending`. The task is re-queued behind its siblings, and its readiness stays set, so no edge is lost. This keeps the `max_polls_per_tick` design and also bounds a single poll. The change touches `task` (budget storage) and `net::reactor` (consumption). Update the `task/_dev/DESIGN.md` §Non-goals sentence "Fairness is enforced by …". Consider documenting `EMFILE` back-off for accept loops (`yield_now().await` until `akku::time` exists).
2. **MEDIUM (concurrent acceptors):** either (a) store a small waiter list for the listener's read direction (`Vec<Waker>` deduplicated with `will_wake`, all woken on readiness, with a bound such as `max_tasks`), or (b) make `accept`/`poll_accept` take `&mut self` and drop the `Sync` claim. Option (a) matches tokio and keeps the `Arc<AsyncTcpListener>` pattern working. Fix `DESIGN.md:592` either way.
3. **MEDIUM (Windows inheritance):** replace `socket()` with `WSASocketW(family, SOCK_STREAM, IPPROTO_TCP, null, 0, WSA_FLAG_OVERLAPPED | WSA_FLAG_NO_HANDLE_INHERIT)`, with the same fallback std uses (retry without `NO_HANDLE_INHERIT` on `WSAEINVAL`/`WSAEPROTOTYPE`, then `SetHandleInformation(HANDLE_FLAG_INHERIT, 0)`). This is one new FFI declaration in the already allowlisted `wsapoll.rs`, plus its `// SAFETY:` comment and a `DESIGN.md` §Dependencies row.
4. **LOWs:** clamp `max_io_events_per_tick`; add the `# Blocking` / platform-minimum rustdoc notes; add a "matches std" comment on `sin6_flowinfo`; make the WSAPoll wake drain fail loudly or recreate the pair.

## Re-audit (Checker, 2026-11-26): PASS

Checked against the working tree on top of `862104b`. Gate: `smd` fmt, clippy (with and without all features), workspace tests, rustdoc `-D warnings`, MSRV 1.85, `check-unsafe.sh` (3 allowlisted files), `catalog check`, and 3 runs of `--test task --test net`, all green. Also green on the host: macOS `task`/`io`/`net` tests and `x86_64-pc-windows-gnu` `check --all-targets`.

- **CRITICAL (budget): fixed.** `poll_ready` and `poll_io` check `poll_budget` before touching state, and they spend budget only on `Ready`. Neither `Pending` nor the `WouldBlock` retry spends any, and a budget yield never clears readiness, so no edge is lost on `epoll` or `kqueue`. `poll_connected`, `poll_accept`, and stream I/O all go through these functions, and `bind`/`connect` spend one unit through `coop_step`. All five regression tests use a 4,096-op bound against 64 Ki to 100 Ki hog operations. Without the fix each would report the full hog count and fail, and none depends on timing.
- **MEDIUM (shared listener): fixed.** Task and root wakers are rebuilt from the same `Arc`, so `will_wake` dedupe holds a task to one entry. The set is bounded by `max_tasks + 1`, saturating and clamped to `65_537`, which is at most about 1 MiB per direction. On readiness and shutdown the whole set is drained, and on overflow it is drained and woken early. `remove` on the register-error path handles both modes. All of this happens under the per-source `state` mutex, and every wake runs after the guard is dropped. Streams stay `Single`, and every waker-registering stream path is `&mut self` or a split half (`poll_read_ref`/`poll_write_ref` are private). Wake-all on readiness is `O(waiters)` per event, as in tokio, which is acceptable.
- **MEDIUM (Windows inheritance): fixed.** Verified against rust-lang/rust `library/std/src/sys/pal/windows/c/windows_sys.rs` (`gh api`). `WSASocketW(i32, i32, i32, *const WSAPROTOCOL_INFOW, GROUP = u32, u32) -> SOCKET = usize` and `SetHandleInformation(HANDLE, u32, u32) -> BOOL` match, with `extern "system"`, `ws2_32` and `kernel32`. The constants match: `WSA_FLAG_OVERLAPPED = 1`, `WSA_FLAG_NO_HANDLE_INHERIT = 128`, `HANDLE_FLAG_INHERIT = 1`, `WSAEINVAL = 10022`, `WSAEPROTOTYPE = 10041`. The fallback matches std `Socket::new` exactly. The `SOCKET` is adopted into `OwnedSocket` right after the `INVALID_SOCKET` check, so a `clear_inherit` error closes it, with no leak and no double close. `WSA_FLAG_OVERLAPPED` is what plain `socket()` already implied, so `FIONBIO`, `WSAPoll`, and `connect` behave the same. Every new `unsafe` block, including the test-only `GetHandleInformation`, has a `// SAFETY:` comment and stays in the allowlisted `wsapoll.rs`.
- **LOWs: done as listed.** The flowinfo comments, the `1..=65_536` clamp, `wake_all` (no lock held, first payload re-raised after the batch), and the rustdoc sections are all in place.

Remaining LOWs (new, none blocking):
- If a single task (or a small `max_tasks`) holds more distinct live wakers on one listener than the cap, for example a combinator with per-child wakers that polls several `accept` futures, each park evicts and wakes the whole set. That cycles as a busy re-poll until a connection arrives. It is CPU only, with no lost wakeup, and needs trusted misconfiguration.
- If a waker in the `overflow` batch of `poll_ready` panics, the `arm` call for the current registration is skipped. The panic then ends the polling task, so this is pathological.
- The Windows `#[cfg(windows)]` inheritance tests are compile-checked only, and `ready_one_byte_read_loop_yields_to_siblings` and `copy_to_between_ready_sockets_yields_to_siblings` assume 64 KiB fits in the loopback buffers before the reader starts. The writer thread is joined on the runtime thread. `os-test (windows-latest)` CI has to confirm both.
- Carried over: the WSAPoll wake-pair drain spin, the Darwin `CLOEXEC` race, the WSAPoll O(n) rebuild, and the `SIGPIPE` test gap.
