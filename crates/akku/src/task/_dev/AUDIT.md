## Re-audit (Checker, 2026-11-26): PASS

Checked against the working tree on top of `862104b`. **The CRITICAL is fixed.** `with_budget` (`mod.rs:903`) wraps every `run_task` poll and every root poll, and a `Drop` guard restores the previous value on return and on unwind. A nested `block_on` panics in `enter` before it sets any budget. `spawn` never polls inline, so no budget leaks between tasks. Code outside a poll (`finish`, `drop_harness_guarded`, `wake_all`) runs with `None`, which is unconstrained but performs no socket polls. On the exhausted path, `poll_budget` defers the waker through `defer_wake` without touching readiness. `has_work` sees the non-empty `deferred` list, so the next turn is `Duration::ZERO`: there is no lost wakeup, the reactor is turned before the task re-runs, and there is no idle spin, because the budget is spent only by `Ready` operations. `defer_wake` dedupes against the last waker, which bounds the list by the polls done. `yield_now` and `max_polls_per_tick` are unchanged in behaviour.

`wake_all` takes its batch out of the lock before waking (`deferred` in `tick`, `wake` in `Reactor::turn`/`shutdown`, `overflow` after the `state` guard is dropped), so no user waker runs under a runtime lock. Re-raising leaves the runtime consistent: `deferred` was already taken, and the event buffer was already restored. The regression tests would fail without the fixes. `panicking_waker_does_not_lose_other_deferred_wakeups` would hang into the watchdog, and the clamp test would panic or OOM. Tests diff vs `862104b`: additions only. No new public name.

Remaining LOWs (new, none blocking):
- If `wake_all` re-raises from `Reactor::turn`, `tick` skips `parked.store(false)`. The only effect is extra `unpark` calls until the next tick resets it. This takes a panicking user waker.
- If a socket is polled from a foreign executor nested inside an akku task (for example `futures::executor::block_on(stream.read(..))`) once the budget is spent, its wake is deferred until the outer task returns, so it hangs. This pattern already hangs today on any non-ready socket, because no reactor turn runs, so it is not a regression. Document it with the `# Cooperative I/O budget` notes when convenient.
- Carried over: the third-order panicking payload `Drop` (`drop_harness_guarded`).
