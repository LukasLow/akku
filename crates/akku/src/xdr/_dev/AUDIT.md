### Suggested fixes for Worker

1. **CRITICAL (`mod.rs:1292-1321`):** In `Decoder::decode_array`, inside the `for _ in 0..count` loop, record `let before = dec.pos;` before `decode_item(dec)?`. If `dec.pos == before`, return an error immediately (e.g. `Error::LengthLimit { offset: item_offset, len: count, limit: 0 }` or a dedicated `#[non_exhaustive]` variant) — in RFC 4506 §6.3, variable-length array elements cannot be `void` / zero wire bytes (`count == 0` still succeeds because the loop does not execute). Also check `decode_fixed_array_vec` if `count` can be large with 0-byte items (at minimum document that `count` must be a trusted schema constant).
2. **MEDIUM (`mod.rs:125, 1272, 1315`):** Change `(MAX_PREALLOC_BYTES / elem_size).max(1)` to `MAX_PREALLOC_BYTES / elem_size` (returns `0` when `elem_size > MAX_PREALLOC_BYTES`), and pass `dec.remaining().min(dec.limits.max_total_bytes.saturating_sub(dec.pos))` into `initial_array_capacity`.
3. **MEDIUM (`mod.rs:711-726, 896-902, 1228-1239`):** Replace manual `depth += 1` / `depth -= 1` / `truncate` with private RAII `Drop` guards (`EncoderNestGuard`, `EncoderTruncateGuard`, `DecoderDepthGuard`) that restore `depth` unconditionally and truncate `Encoder::buf` unless disarmed on `Ok`.
4. **MEDIUM (`mod.rs:461-465` vs `:58-61, 423-424, 662-699`):** Align implementation and rustdoc: either (a) make `Encoder::nest` save `let checkpoint = self.buf.len()` on entry (rolling back only its own scope on error/panic), remove `self.buf.truncate(self.start_len)` from `Encoder::fail` for pre-write validation checks (which have not mutated `buf`), and keep `Encoder::encode` / `encode_into` rolling back to `self.start_len` (note: all existing `tests.rs` tests still pass because top-level `nest` has `checkpoint == start_len`), **or** (b) explicitly document on `Encoder` and every fallible method that *any* error truncates the entire `Encoder` back to `start_len` and poisons prior writes. Option (a) is safer and prevents silent erasure on error recovery.
