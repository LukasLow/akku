# Releasing

## Version

`[workspace.package].version` in `Cargo.toml` is the single source of truth.
The three crates share it.

## Changelog

Every user-visible change gets a changie fragment in `.changes/unreleased/`:

```sh
changie new
```

The fragment has a `kind` (`Added`, `Changed`, `Fixed`, `Security`, …) and an
optional explicit `version` bump. `CHANGELOG.md` is generated by changie.

## Prepare a release

```sh
python3 .github/scripts/release.py auto
# or an explicit version:
python3 .github/scripts/release.py 0.1.0
```

This updates `Cargo.toml`, runs `cargo update --workspace`, batches and merges
the changelog, and writes `releases/v<version>-<date>.md`. It does not commit,
tag or publish.

## CI gates

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test -p akku --no-default-features --locked
cargo test --workspace --all-features --locked
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps
python3 .github/scripts/release.py --check
```

## Publishing

The intended path is crates.io Trusted Publishing (OIDC) in
`.github/workflows/release.yml`:

1. `akku-drive`
2. wait for the registry
3. `akku`
4. wait for the registry
5. `akku-cli`

Trusted Publishing must be configured for all three crates on crates.io. Until
then, a release is published manually in that order.

`0.0.1` was published manually. Its package metadata records Apache-2.0; the
repository and future releases use MPL-2.0.
